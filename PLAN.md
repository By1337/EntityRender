# EntityRender: решения и оставшаяся работа

## Зафиксировано

- Самостоятельная библиотека без BLib. API / core / dumper.
- Базовую библиотеку сначала доводим на 1.21.4 / Java 21; при обновлении
  предыдущая версия фиксируется отдельной веткой. Выбор реализации загрузчиком —
  задача потребителя, универсальный runtime внутри core не делаем.
- Bukkit-типы вместо собственного набора enum. NMS остаётся в core.
- Компактные metadata, общая схема, dirty-маска. Без NMS Entity на каждый экземпляр.
- NMS сериализует значения и готовые пакеты; Netty flush делает сервер.
- Dumper запускает локальный Mojang-named JAR сам, ничего не скачивает и не ремапит.
- Поддержка старых анимаций находится в будущем BCasesV2-адаптере, не в новом API.

## Готово

- Дамп 1.21.4 и 26.3, стабильные схемы и hex-эталоны, diff, verify.
- Генерация черновой иерархии API / core и индексов metadata.
- Типизированные ключи и layouts генерируются в GeneratedMetadata с NMS namespace.
  Ручной Layouts удалён, проверенные defaults — отдельные входные правила генератора.
- Runtime перенесён с 26.3 на 1.21.4: ArmorStand и все три Display-типа; общая инфраструктура metadata,
  координат, зрителей, очереди изменений, lifecycle, экипировки ArmorStand.
- Проверки NMS-пакетов и отдельный временный Paper-сервер с тестовым плагином.
- Снимок рабочей реализации 26.3 до переноса сохранён в .entityrender/snapshots.
- Сгенерирован runtime остальных сущностей; начальные состояния кешируются из NMS
  один раз на тип. Добавлены общие фабрики, экипировка, spawn-only состояния и helpers.
- Добавлены interact-хуки с переносом callback в серверный поток и групповые trackers.
- Версионные ветки 1.21.4–1.21.11, 26.1.2 и 26.2; main — 26.3.
- Для каждой версии: сборка, независимые повторные дампы / hex и живой Paper sweep.
  Полная таблица находится в VERSIONS.md. На 26.3: 158 типов и 1505 свойств,
  плюс взаимодействия, trackers, native snapshots и dirty batching.
- Различия native конструкторов, пакетных протоколов, registry-конвертеров и пакетов
  взаимодействий остаются в соответствующих версиях core; API не зависит от BLib.

## Async-прототип в main (26.3)

- API создания/изменения/видимости доступен из async/virtual threads; инициализация сервиса — main.
- Atomic metadata words, CAS packed helpers, публикация owned-снимков и отдельный transport state.
- Общие на plugin owner sampler игроков, chunk deltas, spatial index, session guards и worker.
- Персональные голограммы через ручные show/hide, без обязательного автоматического tracker.
- Main-thread ID reservation по 4096, асинхронная выдача и непрерывные девять ID для дракона.
- Проверки: 6000 concurrent create/close, dirty-drain races, packed helpers, close/publication,
  персональные snapshots, chunks/respawn и legacy automatic flush. Клиентская картинка и benchmarks — далее.
- Старые ветки пока сохраняют прежнюю потоковую модель. Портировать после оценки main.

## Дальше

1. Загрузить полный vanilla registry / item component context в дампере, закрыть
   UNSUPPORTED hex-образцы. Не подставлять выдуманные IDs динамических реестров.
2. Расширить семантические правила генерации (имена, битовые флаги, Bukkit-конвертеры).
   Defaults после конструктора уже вынесены в воспроизводимые правила. Structural dump
   остаётся независимым источником истины для diff.
3. При необходимости расширить отдельный API контекстных сущностей: player, fishing hook.
4. Проверить картинку и взаимодействия настоящим клиентом. Затем измерить память,
   CPU и аллокации для массового создания / обновления / рассылки сущностей.
   Текущая структура рассчитана на batching, но измеренного выигрыша пока не заявляем.
5. BCasesV2: ASM-ремап старых аддонов, совместимые YAML/Codec-адаптеры и проверка семи
   JAR из BCases/run/anims. Старый BCases обновляется отдельно, его код не менялся.
